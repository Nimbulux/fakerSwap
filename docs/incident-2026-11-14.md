# 事故记录：2026-11-14 21:15 账号数据被覆盖

## 结论

测试「源数据获取 → 中止」时，插件从**不安全的状态**（标题屏，进程栈顶层是 `GenericProcess`）强行注入了
`DataSaveProcess`，游戏把一份**默认 UserData** 通过 `UpsertUserAll` 上传；服务端对 `userData` 是整表覆盖语义，
于是档案被刷成空档。

## 证据（`GetUserPreviewApi`，同一 uid <源uid>）

| 时间 | playerRating | nameplateId | iconId | totalAwake | lastLoginDate |
|---|---|---|---|---|---|
| 20:54（事前） | 13700 | 305602 | 302 | 19 | 2026-11-13 23:55:11 |
| 21:19（事后） | 0 | 1 | 1 | 0 | "" |

事后侧 `dailyBonusDate` = `2026-11-14 22:15:22`（= 中止时刻），`lastPlayDate` 同步被写。

## 触发链

```
[cmd] abort  (Phase=SourceReading)
LoginHooks: forced DataSave (logout) from Process.GenericProcess
LoginHooks: DataSave started (#1)
[stage] Other -> DataSave (UserDataULProcess)
UpsertUserAll(userData = 默认值)  →  服务端整表覆盖
```

根因三连：
1. `GameStageTracker` 当时把标题屏判成 `Other`（`GenericProcess` 挡在 `EntryProcess` 上面）；
2. 登出策略按"阶段"而不是"本会话是否有 playlog"选择路径 → 走了 `Fade→DataSaveProcess`；
3. `ForceDataSave` 没有校验"当前进程可安全收尾"和"UserData 有实质内容"。

## 已落地的防护（同日）

| 防护 | 位置 |
|---|---|
| **只读闸门 `SafeNoWrite`（默认 true）** | `Core/WriteGuard.cs` + `Core/ModConfig.cs`；`UserDataPatcher.Commit/Apply/CommitBatch`、`PayloadRewriter.TryRewrite`、`LoginHooks.ForceDataSave` 全部过闸 |
| **写前必备份** | `BackupStore.SavePreWrite` → `FakerSwap/Backup/pre-write-*.json`；备份失败则拒绝写 |
| `GenericProcess` 当过渡进程跳过 | `Flow/GameStagePump.cs` |
| 登出按 playlog 决定 | 无 playlog → 只 `ForceTimeUp`（模拟超时），永不退化 DataSave |
| `ForceDataSave` 校验可用进程 | `Flow/LoginHooks.cs` |
| 紧急脱出（按住 End 3s）、中止去重 | `Core/EmergencyExit.cs`、`RebirthFlow` 收尾通道 |

## 恢复清单

1. **服务端**：拿 21:15 之前的 `user_data` / `user_music_detail` / 相关表快照恢复（AquaDX 数据库）。
2. 若有 Astral `data/<源uid>.json` 或其它账号备份，可直接灌回。
3. 恢复后先跑**只读**验证：`source-acquire` 全流程（登录→选歌页→`ReadLive`→备份→`ForceTimeUp` 登出），
   确认 `FakerSwap/Backup/用户名-*.json` 里的条数与 rating 正确。
4. 写路径验证顺序：单曲 → `WriteMode=Memory` → `ReadLive` 核对 → 再开 `Both` 整批。

## 教训

- 任何"强制推进游戏流程"的操作，都必须先证明当前状态是**可安全收尾**的。
- 写账号前必须先落一份全量备份，且备份失败即拒绝写。
- 新功能默认只读，写能力显式开启。
