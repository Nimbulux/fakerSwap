# 判定可用性矩阵（操作员提供，实现依据）

| 判定 | tap | 保护tap | hold | 保护hold | 星星头 | 保护星星头 | 星星身子 | 绝赞 | 保护绝赞 | touch | touchhold |
|---|---|---|---|---|---|---|---|---|---|---|---|
| **大P (CriticalPerfect)** | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| **小P (Perfect)** | 是 | **否** | 是 | 是 | 是 | **否** | **否** | 是 | **否** | 极少 | 是 |
| **粉 GREAT** | 是 | **否** | 是 | 是 | 是 | **否** | 是 | 是 | **否** | 少 | 是 |
| **绿 GOOD** | 是 | **否** | 是 | 是 | 是 | **否** | 是 | 是 | 是 | 少 | 是 |
| **掉 MISS** | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |

## 关键结论

1. **「保护」类音符（保护 tap / 保护 hold / 保护星星头 / 保护绝赞）**
   - 只能出 **大P** 或 **MISS**
   - **不可能**出 小P / GREAT / GOOD
2. **星星身子**
   - **永远不会小P**
   - 但可以 GREAT / GOOD
3. **星星头**
   - 大P / 小P / GREAT 都可以
   - **不能 GOOD**
4. **TOUCH**
   - 小P 极少、GREAT/GOOD 少
   - touchhold 正常
5. **MISS** 所有类型都可能
6. **大P 所有类型都可能**

## 另一条真实性要求

- **CP : Perfect 应大约 1 : 1 上下浮动**（不是全 CP）
- **分数以 CP（粉扣）为主**
- 目前实现的问题：TAP/HOLD/TOUCH/BREAK 全 CP、SLIDE 出现 51 个 GREAT —— 与矩阵严重不符

## 实现落点

`FakerSwap/Flow/ScoreHooks.cs` 的判定等级分配（`level[]`：0=CP, 1=Perfect, 2=GREAT, 3=GOOD, -1=MISS）

需要：
1. 为每个音符记录「类型 + 是否保护 + 星星头/身」的可用判定集合
2. 分配时只在可用集合里取
3. 目标 CP:Perfect ≈ 1:1
